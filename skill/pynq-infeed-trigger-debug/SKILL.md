# PYNQ入料触发联调Skill

## 用途

本Skill整理PYNQ板端入料检测联调经验，用于辅助完成Overlay加载、AXI GPIO配置、传感器状态读取和触发功能检查。通过统一检查步骤，减少接线、地址配置和程序状态不一致造成的排查困难。

本项目的PC/PS/PL职责应保持清晰：AI推理在PC端；PS负责软件控制与任务处理；PL负责对射传感器信号的同步和滤波，并保存入料触发标志；PS读取标志并处理任务后，将其清除。

## 输入信息

开始联调前收集：

- PYNQ板卡型号。
- 配套的`.bit`与`.hwh`文件路径和文件名。
- AXI GPIO实例名称、基地址及通道配置。
- 传感器连接方式、输入引脚和有效电平。
- 触发模块控制位、状态位定义及寄存器地址。
- 加载失败或输入异常时的完整报错、Notebook输出和相关运行日志。

信息缺失时先标注未知项；不要自行推断板卡引脚、地址或寄存器位定义。

## 联调流程

1. **核对Overlay文件**：确认bit与hwh来自同一硬件工程和同一构建版本；在目标路径加载Overlay，确认无加载错误。
2. **核对IP映射**：检查`overlay.ip_dict`中的AXI GPIO名称、基地址及通道信息，和硬件工程地址映射对照。名称存在只证明Overlay发现该IP，不证明物理接线正确。
3. **核对GPIO方向**：根据AXI GPIO通道配置和工程定义确认输入/输出方向。只有寄存器定义明确时才执行写操作；不要把输入通道当作输出通道写入。
4. **读取传感器状态**：分别操作通光和遮挡状态，读取GPIO输入，确认读数能随传感器实际状态变化，并确认高低电平与设定的有效电平一致。
5. **检查触发处理**：依次执行正常入料、持续遮挡和释放后再次入料。记录传感器电平、GPIO读数、触发状态和触发计数，确认持续遮挡不重复触发，释放后新任务可以重新触发。
6. **逐层定位异常**：结合报错和日志依次核对供电与共地、信号接线、有效电平、AXI GPIO地址和方向、寄存器配置、PL握手状态及PS程序状态。每次只改变一个待查因素，并记录改变前后的读数。

## 输出内容

联调记录应包含：

- 板卡型号、bit/hwh文件名及加载结果。
- AXI GPIO名称、地址、通道方向及核对依据。
- 传感器通光/遮挡时的实际输入读数和有效电平判断。
- 三类触发测试的步骤、状态变化、触发次数；有测量条件时记录响应时间。
- 异常现象、日志、排查项及结论，并将已验证和待验证内容分开。

据此判断问题更可能来自传感器输入、PL逻辑还是PS程序。结论应基于读取值或可观察日志，不用推测代替测量。

## 本项目已有验证基础

本项目已完成Overlay加载、AXI GPIO读写及对射传感器入料触发联调。人工操作检查反馈通过的情况包括正常入料、持续遮挡不重复触发，以及释放后重新入料可开始新任务。目前没有量化测试次数或响应时间统计。该Skill尚未完成独立封装后的跨项目验证，后续需结合使用记录完善说明和示例。

本项目中AXI IIC与PCA9685舵机接口已保留，但机械舵机分拣尚未完成；IIC联调不能作为舵机分拣已完成的证据。红外检测已实现图像采集、分割分析和结果展示。受开发时间及测试条件限制，检测精度仍需进一步优化。触发模块仿真有打包记录，见board/fruit_trigger_package/VALIDATION.txt；该记录对应打包时版本，本次未重新运行。基线对比和独立复现仍待补充。

## 适用范围与限制

本Skill适用于具有明确寄存器定义的PYNQ数字输入检测项目。更换板卡、传感器或硬件工程后，必须重新核对管脚、电平、GPIO通道方向和地址映射；不能直接沿用本项目的控制字和状态位。模拟量采集、其他通信接口或不同触发逻辑需按实际硬件另行调整。
